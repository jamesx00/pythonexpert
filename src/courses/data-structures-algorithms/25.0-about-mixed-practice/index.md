## This Section Is Optional &#x1F6A9;

You've finished the guided path. Everything you need is in the earlier sections, and you can stop here.

Mixed Practice is for learners who want to practise the step the earlier sections did for you: **working out which pattern a problem needs**. In a pattern section you knew the technique before you read the problem. Here, the problems come in a mixed order with no section name to give the pattern away.

## How It Works &#x1F9ED;

- **The problems aren't labelled by pattern,** and they're mixed so that neighbouring problems use different techniques.
- **Every problem appeared earlier in the course.** These are the same problems, with the same tests, from the Arrays & Hashing, Two Pointers, Sliding Window, Stack and Binary Search sections. If you remember one, that's fine: say which pattern it uses and why before you write any code, then solve it again from scratch.
- **The first hint names the pattern.** Make your guess first, then reveal hint 1 to check it. The hints after that are the same as in the original lesson.

## Before You Start &#x1F4CC;

Use the routine from *How to Approach a New Problem* on each one: restate the problem, try small examples, write the brute force, find the bottleneck, pick a pattern, and list edge cases. The target complexity under each problem statement is a clue too, so read it before you pick a pattern.
